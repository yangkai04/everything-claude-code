# 医疗 EMR 开发模式（Healthcare EMR Development Patterns）

构建电子病历（EMR）和电子健康档案（EHR）系统的模式指南。优先保障患者安全、临床准确性和医生使用效率。

## 适用场景

- 构建患者就诊工作流（主诉、检查、诊断、处方）
- 实现临床病历记录（结构化 + 自由文本 + 语音转文字）
- 设计带药物相互作用检查的处方/用药模块
- 集成临床决策支持系统（CDSS）
- 构建带参考范围高亮的检验结果展示
- 实现临床数据的审计轨迹
- 为临床数据录入设计医疗级无障碍 UI

## 工作原理

### 患者安全优先

每一个设计决策都必须经过以下评估："这会伤害患者吗？"

- 药物相互作用**必须**告警，不得静默放行
- 异常检验值**必须**有视觉标记
- 危急生命体征**必须**触发升级工作流
- 任何临床数据修改都不得缺少审计轨迹

### 单页就诊流程

临床就诊应在单页内垂直展开——不切换标签页：

```
患者信息头部（固定置顶，始终可见）
├── 人口学信息、过敏史、当前用药
│
就诊流程（垂直滚动）
├── 1. 主诉（结构化模板 + 自由文本）
├── 2. 现病史
├── 3. 体格检查（按系统）
├── 4. 生命体征（自动触发临床评分）
├── 5. 诊断（ICD-10/SNOMED 搜索）
├── 6. 用药（药物数据库 + 相互作用检查）
├── 7. 辅助检查（检验/影像医嘱）
├── 8. 治疗方案与随访
└── 9. 签署 / 锁定 / 打印
```

### 智能模板系统

```typescript
interface ClinicalTemplate {
  id: string;
  name: string;             // 如 "胸痛"
  chips: string[];          // 可点击的症状标签
  requiredFields: string[]; // 必填数据项
  redFlags: string[];       // 触发不可关闭告警
  icdSuggestions: string[]; // 预映射的诊断编码
}
```

任何模板中的红旗症状必须触发可见的、不可关闭的告警——不得使用 Toast 通知。

### 用药安全模式

```
用户选择药物
  → 检查当前用药的相互作用
  → 检查本次就诊用药的相互作用
  → 检查患者过敏史
  → 根据体重/年龄/肾功能验证剂量
  → 如为危急（CRITICAL）相互作用：完全阻断开具处方
  → 临床医生必须记录覆盖原因才能越过阻断继续
  → 如为重要（MAJOR）相互作用：显示警告，要求确认
  → 在审计轨迹中记录所有告警和覆盖原因
```

危急相互作用**默认阻断开具处方**。临床医生必须明确覆盖并在审计轨迹中留存记录原因。系统绝不允许静默放行危急相互作用。

### 锁定就诊记录模式

临床就诊签署后：
- 不允许编辑——只能添加附录（独立的关联记录）
- 原始记录和附录都显示在患者时间轴上
- 审计轨迹记录签署人、签署时间及所有附录记录

### 临床数据的 UI 模式

**生命体征显示：** 当前值带正常范围高亮（绿/黄/红），与前次对比的趋势箭头，自动计算临床评分（NEWS2、qSOFA），内联展示升级指导。

**检验结果显示：** 正常范围高亮，与前次值对比，危急值显示不可关闭告警，采集/检测时间戳，待报结果及预计回报时间。

**处方 PDF：** 一键生成，包含患者人口学信息、过敏史、诊断、药物详情（通用名 + 商品名、剂量、途径、频次、疗程）、临床医生签名栏。

### 医疗级无障碍

医疗 UI 的要求比普通 Web 应用更严格：
- 最低 4.5:1 对比度（WCAG AA）——临床医生在各种光线条件下工作
- 大触控目标（最小 44×44px）——适应戴手套或紧急状态下的操作
- 键盘导航——满足快速录入的高级用户需求
- 不能仅依赖颜色区分——颜色必须搭配文字/图标（考虑色觉障碍的临床医生）
- 所有表单字段配备屏幕阅读器标签
- 临床告警不使用自动关闭的 Toast——临床医生必须主动确认

### 反模式

- 在浏览器 localStorage 中存储临床数据
- 药物相互作用检查静默失败
- 危急临床告警使用可关闭的 Toast
- 基于标签页的就诊 UI，将临床工作流碎片化
- 允许编辑已签署/锁定的就诊记录
- 展示临床数据时缺少审计轨迹
- 临床数据结构使用 `any` 类型

## 示例

### 示例 1：患者就诊流程

```
医生为患者 #4521 开启就诊
  → 固定头部显示："Rajesh M，58岁男，过敏：青霉素，当前用药：二甲双胍 500mg"
  → 主诉：选择"胸痛"模板
    → 点击标签：" substernal（胸骨后）"、"向左臂放射"、"压榨性"
    → 红旗症状"压榨性胸骨后胸痛"触发不可关闭告警
  → 检查：心血管系统——"S1 S2 正常，无杂音"
  → 生命体征：HR 110，BP 90/60，SpO2 94%
    → NEWS2 自动计算：评分 8，高风险，显示升级告警
  → 诊断：搜索"ACS"→ 选择 ICD-10 I21.9
  → 用药：选择阿司匹林 300mg
    → CDSS 检查与二甲双胍的相互作用：无相互作用
  → 签署就诊记录 → 锁定，此后仅可添加附录
```

### 示例 2：用药安全工作流

```
医生为患者 #4521 开具华法林处方
  → CDSS 检测：华法林 + 阿司匹林 = 危急（CRITICAL）相互作用
  → UI：红色不可关闭弹窗阻断处方开具
  → 医生点击"带原因覆盖"
  → 输入："获益大于风险——已制定 INR 监测方案"
  → 覆盖原因 + 告警存入审计轨迹
  → 处方继续开具，并有书面覆盖记录
```

### 示例 3：锁定就诊记录 + 附录

```
就诊记录 #E-2024-0891 由 Shah 医生于 14:30 签署
  → 所有字段锁定——不显示编辑按钮
  → 显示"添加附录"按钮
  → Shah 医生点击附录，添加："已收到检验结果——肌钙蛋白升高"
  → 新记录 E-2024-0891-A1 关联至原记录
  → 时间轴同时显示：原始就诊记录 + 带时间戳的附录
```
